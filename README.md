# distributed-training-framework-nccl

> [!NOTE]
> **Status: early scaffold.** This repository has a minimal C++ wrapper around NCCL
> with pybind11 bindings, and not much more. It is **not** a working training
> framework. Nothing has been benchmarked, and this README makes no performance
> claims. Any number added later will be generated by a committed script under
> `bench/` and will name the GPU, driver, NCCL and PyTorch versions it was measured on.

## What exists today

About 250 lines of C++/CUDA in `csrc/`:

| Component | Files | What it does |
|---|---|---|
| `Communicator` | `csrc/include/dtf/communicator.h`, `csrc/core/communicator.cpp` | Holds an `ncclComm_t`, rank and world size. Wraps `ncclGetUniqueId` and `ncclCommInitRank`; the destructor calls `ncclCommDestroy`. |
| `CollectiveOps` | `csrc/include/dtf/collective_ops.h`, `csrc/core/collective_ops.cpp` | Static wrappers for `ncclAllReduce`, `ncclBroadcast` and `ncclAllGather` on a given CUDA stream. |
| `ProcessGroup` | `csrc/include/dtf/process_group.h`, `csrc/core/process_group.cpp` | Owns a `Communicator` and initialises it from a unique ID. |
| Error macros | `csrc/include/dtf/utils.h` | `DTF_CHECK` and `NCCL_CHECK`, which throw `std::runtime_error`. |
| Memory helpers | `csrc/cuda/memory_utils.cu` | `cudaMalloc` / `cudaFree` wrappers. |
| Python bindings | `csrc/bindings/pybind.cpp` | Module `dtf_C`: `get_unique_id()` (returns bytes), plus the `Communicator` and `ProcessGroup` classes. |

## What does not exist yet

- **The Python package is empty.** `import dtf` succeeds but exposes nothing. There is
  no `dtf.init`, no `DistributedModel` and no `dtf-launch` command.
- **Python can't run collectives.** `CollectiveOps` is not exposed in the bindings, and
  reduce-scatter is not implemented.
- **No tests or CI.** The files under `tests/` are empty placeholders.
- **The build is unverified.** It has not been confirmed on a CUDA host, and the CMake
  setup has known issues (see below).
- Empty placeholder files are left over from an earlier, broader plan, including
  `dtf/parallelism/`, `dtf/compression/`, `examples/`, `docs/` and the CUDA kernels
  `compression.cu` and `cast_fp16_bf16.cu`. They are not features.
  [`PROJECT_STRUCTURE.md`](PROJECT_STRUCTURE.md) marks which files are empty.

## Known issues

| Area | Issue |
|---|---|
| Build | `find_package(CUDA)` is deprecated; `CMAKE_CUDA_ARCHITECTURES` is not set; NCCL is searched for only in `/usr/local/nccl`, so `-DNCCL_ROOT` is ignored; a missing NCCL is only a warning, so the failure shows up later at link time; pybind11 is located with `execute_process` instead of `find_package(pybind11)`. |
| Teardown | The destructor always calls `ncclCommDestroy`. After a peer failure this can block forever; the error path should call `ncclCommAbort`. |
| Errors | `NCCL_CHECK` drops the rank, operation and communicator from its message; `ncclInProgress` (non-blocking mode) is not handled; the result of `cudaFree` is ignored. |

## Direction

The original plan here was to re-implement data, tensor and pipeline parallelism plus
gradient compression from scratch. That plan has been dropped: PyTorch DDP/FSDP,
Megatron-LM and DeepSpeed already solve that problem well.

The NCCL layer in this repo will be scoped toward **failure handling** for NCCL-based
training: non-blocking communicator init with deadlines, async error polling
(`ncclCommGetAsyncError`) and `ncclCommAbort`. The design will be written up in
`docs/design.md` before any feature code lands.

## Building (unverified)

Building requires CUDA, NCCL and pybind11. Until the CMake issues above are fixed,
treat this as untested:

```bash
git clone https://github.com/nareshns2004/distributed-training-framework-nccl.git
cd distributed-training-framework-nccl
pip install -e .   # runs CMake through setup.py; needs nvcc and NCCL
```
