# distributed-training-framework-nccl

**A fault-aware NCCL communicator, and the failure experiments that show how NCCL
behaves when a peer dies or hangs.**

> [!NOTE]
> **Status: design done, build not started.** Today the repository has a minimal C++
> wrapper around NCCL with pybind11 bindings, plus the design for what it becomes.
> Nothing has been benchmarked, and this README makes no performance claims. Any number
> added later will be generated by a committed script under `bench/` and will name the
> GPU, driver, NCCL and PyTorch versions it was measured on.

## Why

In NCCL-based training, a dead or hung peer doesn't return an error: `ncclAllReduce`
only enqueues work, so the surviving ranks' kernels never finish. Recovering without
restarting the job needs NCCL APIs that `torch.distributed` hides: non-blocking init
with a deadline, `ncclCommGetAsyncError`, `ncclCommAbort` and communicator re-creation.
It also needs clear answers to questions such as "which operations are legal after an
abort?" and "when is the CUDA context poisoned?"

This repo builds that layer on raw NCCL and writes down the answers, with measured
timings. It is the NCCL foundation for
[goodput](https://github.com/nareshns2004/goodput-fault-tolerant-training-orchestrator),
the fault-tolerant training orchestrator, whose in-process restart work depends on
these answers. Training itself stays on standard PyTorch: this is not a replacement for
DDP, FSDP or Megatron.

- Decisions: [`docs/design-decisions.md`](docs/design-decisions.md)

## What exists today

About 250 lines of C++/CUDA in `csrc/`:

| Component | Files | What it does |
|---|---|---|
| `Communicator` | `csrc/include/dtf/communicator.h`, `csrc/core/communicator.cpp` | Holds an `ncclComm_t`, rank and world size. Wraps `ncclGetUniqueId` and `ncclCommInitRank` (blocking); the destructor calls `ncclCommDestroy`. |
| `CollectiveOps` | `csrc/include/dtf/collective_ops.h`, `csrc/core/collective_ops.cpp` | Static wrappers for `ncclAllReduce`, `ncclBroadcast` and `ncclAllGather` on a given CUDA stream. Not yet bound to Python. |
| `ProcessGroup` | `csrc/include/dtf/process_group.h`, `csrc/core/process_group.cpp` | Owns a `Communicator` and initialises it from a unique ID. |
| Error macros | `csrc/include/dtf/utils.h` | `DTF_CHECK` and `NCCL_CHECK`, which throw `std::runtime_error`. |
| Memory helpers | `csrc/cuda/memory_utils.cu` | `cudaMalloc` / `cudaFree` wrappers. |
| Python bindings | `csrc/bindings/pybind.cpp` | Module `dtf_C`: `get_unique_id()` (returns bytes), plus the `Communicator` and `ProcessGroup` classes. |

What is missing: the Python package `dtf` is empty, there are no tests or CI, and the
build has not been verified on a CUDA host.

## Known issues in the existing code

| Area | Issue | Fixed in |
|---|---|---|
| Build | `find_package(CUDA)` is deprecated; `CMAKE_CUDA_ARCHITECTURES` is not set; NCCL is searched for only in `/usr/local/nccl`, so `-DNCCL_ROOT` is ignored; a missing NCCL is only a warning; pybind11 is located with `execute_process` instead of `find_package(pybind11)`. | M2 |
| Teardown | The destructor always calls `ncclCommDestroy`. After a peer failure this can block forever; the error path should call `ncclCommAbort`. | M3 |
| Errors | `NCCL_CHECK` drops the rank and operation from its message; `ncclInProgress` (non-blocking mode) is not handled; the result of `cudaFree` is ignored. | M3 |
| Bindings | Collectives aren't exposed to Python; reduce-scatter is missing. | M3 |

## Roadmap

| Milestone | Content | Status |
|---|---|---|
| M1 | Honest README, repo hygiene, `CLAUDE.md` | done |
| M1b | Design and ADRs | done |
| M2 | Modern CMake; CI with ruff, mypy, CPU tests and a CMake configure step | planned; starts alongside goodput's M2 |
| M3 | Non-blocking init with deadlines, async error poller, abort-all registry, safe teardown, collectives bound to Python; failure experiments X1–X8 written up in `docs/findings/`; measurements E1–E6 | planned |

Out of scope: data, tensor and pipeline parallelism; gradient compression; custom
collective kernels; JAX; an MPI backend. PyTorch and NCCL already do these well. The
watchdog, fault injection, failure classification, checkpointing and restart belong to
goodput.

## Building (unverified)

Building requires CUDA, NCCL and pybind11. Until M2 fixes the CMake setup, treat this as
untested:

```bash
git clone https://github.com/nareshns2004/distributed-training-framework-nccl.git
cd distributed-training-framework-nccl
pip install -e .   # runs CMake through setup.py; needs nvcc and NCCL
```
